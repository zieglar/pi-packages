# 0.2.2 本地 Release Candidate

本工作区准备 CE 0.2.2 本地 npm tarball，当前 npm 正式版仍为 0.2.1。本地 tarball 安装不等于 Registry 安装、hosted CI、发布或真实 Cloud 验收。

## 变更

`CE_TUNNEL_CLIENT_PATH` 表示用户显式选择并信任该外部可执行程序及其安装路径写入者，允许正常 Homebrew 安装等祖先目录具有 group-write。自动发现继续严格准入，使用原有受控目录；显式路径无效时直接拒绝，不回退。没有额外确认、摘要绑定、授权数据库或 Homebrew 白名单。

保留文件类型/可执行性、规范化、symlink/realpath 链、owner、文件自身 group-write、world-write、macOS ACL 和项目路径检查。可识别的 Homebrew wrapper 字面 execTarget 接受相同客户端准入；`$`/反引号展开不被视为字面执行身份证据。Node、Native、凭据、进程 ownership、owned Stop 和 Recovery 不变。

受管 profile 显式设置 `MCP_STDIO_FAILURE_POLICY=exit`，覆盖父环境的 restart 策略。在 0.0.19 中，MCP child 失败会使 client 退出，不再重启 child。CE 不自动拉起、接管 ownership 或重试消息；重新启动前应检查 ownership 并由操作者显式恢复。兼容范围以矩阵中的精确条目为限，包括旧 client 的历史范围。

获准安装的其他有效写入者可能替换 client，恶意代码可取得当前用户权限并读取 Tunnel 凭据。该策略不证明全部写入者、不审计供应链、不消除检查与执行之间的竞争窗口。CE 不负责 client 安装/升级或 Homebrew 权限治理；不要为 CE 修改 Homebrew 权限/ACL 或绕过 Gatekeeper。

## Client 与运行时范围

[兼容矩阵](../../compatibility/README.md)记录与源码绑定的证据：client **0.0.19** 在 macOS arm64 / Pi 1.3.0 / Node 24.21.0、**legacy Tunnel identity** 下完成本地生命周期及手工双向 Cloud E2E。历史 **0.0.16** 资格仅适用于记录中的 RC 运行时。Linux x64 CI 使用官方 0.0.19 和合成 loopback 控制面，覆盖 legacy 与合成 namespaced profile、health、Stop、child failure exit 和清理，不授予真实 Cloud 资格。**真实 namespaced Cloud、Windows/WSL2 集成及 client 0.0.18 仍为 NOT_VERIFIED。** 不据此推断后续 client 版本或已变更源码的资格。

Native 仍是独立发布的固定信任驱动 `ce-sqlite-v0.1.0`，ABI 1 / 内置 SQLite 3.54.1。需显式执行 `/ce-native install` 并重新启动 Pi，再用 `/ce-native verify` 确认 READY。不增加自动安装、升级、修复或回退。

## 候选安装与操作

先执行 `npm install --prefix /absolute/path/to/ce-rc-prefix --omit=dev --ignore-scripts /absolute/path/to/zieglar-pi-chat-exchange-0.2.2.tgz`，再执行 `pi install /absolute/path/to/ce-rc-prefix/node_modules/@zieglar/pi-chat-exchange`。登记已安装目录，不要直接登记 tarball 路径；核对 `pi list` 与已安装 manifest。父进程环境、官方 client 安装入口、Native 准备、Setup 和诊断见[快速开始](../getting-started.zh-CN.md)及 [Tunnel 设置](../tunnel-setup.zh-CN.md)。

更新现有安装前，先 Stop 自己拥有的 Tunnel 并独立核实 STOPPED，正常释放受影响 binding，再退出相关 Pi Host。保留 Store、凭据和 ownership record；UNKNOWN 不等于 STOPPED，关闭 Manager 或 Pi 不会停止 detached client。runtime key/身份及真实 Cloud 窗口需另行操作授权。ACK 只记录接收，不证明任务完成；未知发送结果应先 reconciliation 再决定重试。

## 验证限制

本地打包及已安装 Pi 证据归属于本次 RC，不归属于已发布的 0.2.1 制品。兼容矩阵区分上述限定范围的手工 Cloud 证据与 Linux 合成生命周期检查。独立 latest 监测和同次运行制品传递到实际发布入口仍为 **NOT_VERIFIED**。候选就绪和 PR CI 通过不授予发布权限。
