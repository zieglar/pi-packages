# 0.2.2 local release candidate

This working tree prepares a local npm tarball for CE 0.2.2. The current published npm version remains 0.2.1. Local tarball installation is not Registry installation, hosted CI, publication or real Cloud acceptance.

## Change

`CE_TUNNEL_CLIENT_PATH` now means the user explicitly selects and trusts that external executable and its installation writers. It accepts group-writable ancestor directories such as a normal Homebrew installation. Automatic discovery remains strict and uses the existing controlled directories; an invalid explicit path refuses without fallback. There is no additional confirmation, digest binding, authorization database or Homebrew whitelist.

File type/executability, normalization, symlink/realpath chains, owner, file group-write, world-write, macOS ACL and project-path checks remain. Recognized literal Homebrew wrapper exec targets undergo the same client admission. Dollar/backtick shell expansion is not accepted as literal exec identity evidence. Node, Native, credentials, daemon argv/environment, process ownership, Stop and Recovery are unchanged.

Other effective writers of a selected installation may replace the client. Malicious code may run as the current user and read the Tunnel credential. The policy does not prove all writers, audit supply chains or remove check-to-execution races. CE does not install/upgrade the client or govern Homebrew permissions. Do not change Homebrew permissions/ACLs or bypass Gatekeeper for CE.

## Client and runtime scope

Local macOS arm64 / Pi 1.3.0 / Node 24.21.0 evidence covers client **0.0.16** admission, metadata-only `/ce-tunnel doctor` and a separate version probe. Official client **0.0.18 has not completed CE runtime compatibility validation**. Neither version is qualified here for real Cloud E2E. Linux client execution, Windows/WSL2 integration and all later client versions are not established by these checks.

Native remains the separately released pinned `ce-sqlite-v0.1.0` driver, ABI 1 / bundled SQLite 3.54.1. Explicit `/ce-native install` and a fresh Pi restart are required before `/ce-native verify` reports READY. No automatic install, upgrade, repair or fallback is added.

## Candidate installation and operation

Install the reviewed tarball with `npm install --prefix /absolute/path/to/ce-rc-prefix --omit=dev --ignore-scripts /absolute/path/to/zieglar-pi-chat-exchange-0.2.2.tgz`, then `pi install /absolute/path/to/ce-rc-prefix/node_modules/@zieglar/pi-chat-exchange`. Register the installed directory, not the tarball path. Check `pi list` and the installed manifest. Follow [Getting started](../getting-started.md) and [Tunnel setup](../tunnel-setup.md) for parent environment, official client installation links, Native preparation, Setup and diagnostics.

Before changing an existing installation, Stop the owned Tunnel and independently verify STOPPED, release affected bindings normally, then exit affected Pi Hosts. Preserve Store, credentials and ownership records. UNKNOWN is not STOPPED; closing Manager or Pi does not stop a detached client. Runtime key/identity and a real Cloud window require separate operator authorization. ACK records reception, not task completion; unknown sends require reconciliation before any retry.

## Validation limits

The accepted client fix passed 358 targeted checks and four scoped review lanes; Native-related checks had 10 passes and 7 conditional skips. RC-specific local packaging, installed-Pi and review evidence belongs to the RC report, not to the published 0.2.1 artifact. **Real Cloud transport and ChatGPT ↔ Pi exchange remain NOT_VERIFIED.** Local candidate readiness grants no publication permission.
