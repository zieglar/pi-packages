# CE 0.4.0 本地候选

本版本仍是尚未发布的开发候选。精确 runtime 的 Hosted 与独立 Docker QA Cloud 资格已验证；正式 release workflow 和永久生产采用仍未执行。

## 范围和来源

候选基于开发 main `df0e56ac17e915e237bf245be985d250a86e153b`，保留完整归并的 CE 维护历史。2026-11-22 查询到 npm 最新正式版本为 0.3.6，下载后的 tarball 与 registry SHA-1 `27823ee44e3ef7035d0f03570c248ee7a7a09e28` 及 SHA-512 integrity 均匹配。npm 虽未提供 gitHead，其 registry SLSA statement 指向源码 `ccba6e6d27e183e47ea69f22a6f89548c556ffc2`、workflow run `43752573619/attempts/1`，且 artifact subject digest 与下载制品匹配。这记录的是 registry provenance 解码和完整性核对，不另作 npm 签名独立审计声明。候选 tarball 相对该发行版新增 19 个文件、修改 21 个，没有删除文件。

候选包含归并后的发布后续功能：一步 Session 配对与连接状态、workspace Hook profile 和多 Session 作用域、Session Plugins/状态探针、MCP runtime 身份与路由、`/cenew` 一次性配对和 workspace Hook 继承、当前 Session Desktop 操作及 ChatGPT 共享控件选择。开发侧的 `ce_help` 和通用 CE Skill 均保留。

本次另修复关联回复链，并将 `7ef80d575fd58a179d46759ab4069d974ec8ecc9` 的出站读取指引语义移植到当前扩展，用真实 Host 夹具验证；没有合并旧根目录的脏工作区。operator recovery WIP、pending-delivery 分支、并行 Session UX、Wayforge 和 Session Advisor 成果继续独立保留，未顺带纳入候选。具体分支清单和验证结果见候选报告。

## 关联回复修复

收到的回复可以作为下一条回复的直接父消息。此前 Store 额外要求父消息的关联必须指向自身这个根请求，导致“请求 → 回复 → 确认”的确认步骤在已成功授权读取后，仍返回 `MESSAGE_READ_REJECTED`。

修复仅移除这个根请求限制。直接父消息仍须存在于同一 Exchange、满足准确的发送/接收端点反向配对、晚于调用者成员加入边界，并绑定调用者当前的目标 Owner Session 和 fencing token。发送方仍不能回读自己的出站消息，第三个 Endpoint 不能加入关联链；幂等重放继续返回原 Message 身份。`replyTo` 记录直接父消息，不新增 transcript、payload 或任务所有权推断。

这在源码与隔离 Store 中复现了针对 audits #804、#805、#807、#809、#811 的关联确认失败模式；没有重放或修改那些生产交换。

扩展同时明确：读取工具只使用入站 Message ID；发送结果中的出站 ID 不能由发送 Endpoint 自行读取。`CREATED` 只证明持久化，ACK 只证明接收；CE 不承担 Wayforge 的业务完成判断。

## 兼容性与 Tunnel

- npm 包和 Desktop 插件版本同步为 0.4.0。本候选没有改变 Store schema 或 CE protocol 代际，现有收件方、Owner 和迁移检查继续生效。
- Pi 宿主 peer 版本保持 1.3.0，可选宿主 API 保留能力检查。本地验证使用 Node 24.21.0；Pi host 与 child/SQLite 各自的资格规则不变。
- 相对 npm 0.3.6，Pi TUI 1.3.0 与 TypeBox 从直接运行依赖转为宿主 peer，TypeBox 0.34.52 仍固定为开发依赖；MCP SDK 1.30.1、pi-tui-kit 0.66.0 不变。独立 Desktop ZIP 会显式携带 TypeBox，因为该服务没有 Pi 宿主提供 peer。
- `2026-11-22T08:23:19Z` 从官方上游查到最新稳定 Tunnel 为 **0.0.21**，source SHA `714f2d67844b660af25754f1d19b0360b346b13b`，发布时间 `2026-11-14T18:25:22Z`。
- 实际测试制品为 `tunnel-client-v0.0.21-darwin-arm64.zip`，SHA-256 `353a535d2513f599f9fe7897606e89b3248611453b30203ebddfb6e62fd4f58b`。已用官方 checksum 及 release-workflow Sigstore attestation 校验 tag、source/signer commit 与 hosted-runner 身份。
- 既有生命周期夹具用真实官方 binary，通过 profile、health、正常 Stop、子进程异常退出、故障期间 Stop、cleanup 和 namespaced synthetic profile 检查。资源均为隔离的本地合成控制面和 Store。
- 首次 macOS 夹具因 `/var` 临时路径未规范化而被 Store 拒绝；只将夹具改为 `realpath(tmpdir())`，没有放宽 Store 验证。首个失败及原因保留在报告中。

精确运行时代码证据见[兼容性记录](../../compatibility/evidence/compat-ce-0.4.0-client-0.0.21.json)。记录使用候选提交前的 modified-worktree 基点与 runtime digest，最终提交及制品会在报告中与该 digest 对应。

## 资格限制与发布阻断

正式 CI-verified release client 已更新为 Tunnel 0.0.21。保留的 macOS arm64 本地生命周期、Linux x64 Hosted 离线检查及真实 ChatGPT→Docker QA Cloud 通信分别记录在[兼容证据](../../compatibility/evidence/compat-ce-0.4.0-client-0.0.21.json)中。Cloud 请求、回复、ACK 及显式关联确认与 Store 中三条消息、三条回执、六条相关审计匹配；QA 正常停止后 ownership 为 0。

后续默认 CE 全套运行结果为 **3895 通过、0 失败，保留原有 18 项 skip**，共 3913 项。原始 98 项失败已通过当前契约下的夹具维护和真实关闭竞态修复关闭，其中两处版本预期已在首个候选中修正。另有新增回归确保等待确认时的真实 Stop 不会停止共享服务。根因数量、skip 原因和首败证据见[测试修复报告](../reports/2026-11-22-ce-040-test-repair.md)。

Hosted 在 `cbaf6168d4ad5f4c2409bc2181369f84d77432cb` 上通过：3884 PASS、0 FAIL、29 项原有 skip；相对本地多出的 11 项是 Linux 平台条件。候选后续仅修改证据与说明，保留已验 runtime 和 npm 制品身份。未来获授权的正式 release workflow 仍须为其 dispatched SHA、run、attempt 生成新鲜离线结果，再执行 canonical preflight 和发布。默认兼容驱动与缓存 Native 测试不代表永久生产采用。

独立 QA 容器已停止，专用 volume、可复用配置和 ChatGPT QA 插件保留。生产仍运行 CE 0.3.6；尚未正式发布或永久升级生产。
