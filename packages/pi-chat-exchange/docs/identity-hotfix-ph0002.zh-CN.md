# PH-0001 身份热修复（在 PH-0002 期间获准）

PH-0001 关于 `encodeUlid()` 保留全部 80 位随机位的断言被回归测试推翻，架构要求没有改变。

## 原因和有限修正

旧循环从每个字节输出两个五位字符（重叠两位），只访问字节 0–7，丢弃字节 8–9。因此它只保留了 64 位随机输入，没有编码规范的 ULID 随机负载。修正后的循环用全部十个字节构建 80 位大端整数，输出十六个不重叠的五位组。48 位时间戳循环不变。

外部合同仍为 `ho_<26-character ULID>` 和 `hr_<26-character ULID>`；Crockford 字母表、时间戳位置、ID 长度、前缀、非秘密不透明身份及校验 API 均不变。没有重写已有身份。本包没有持久化身份解码器。`isHandoffId`、`HandoffIdSchema` 和 `ResultIdSchema` 校验格式，不校验被截断的随机负载。仅测试使用的时间戳解码器不依赖随机位假设。现有校验器保持不变，本次有限修复未扩展其较宽松的格式校验。

## RED → GREEN 证据

命令：`mise x pnpm@12.9.1 -- pnpm --filter pi-handoff exec vitest run test/protocol/identity.test.ts`

实现修复前：4 项失败、7 项通过。恢复后的原始回归在时间戳 0 下只把随机字节 9 从 0 改成 1；两次输出均为 `00000000000000000000000000`。其他失败证明了单个位丢失、末字节编码错误，以及独立 80 位解码失败。

修复后：11 项通过。保留时间戳往返覆盖，并增加全部 80 个单位输入、首字节和第十字节规范向量、确定性、独立 bigint 解码、字母表/长度，以及最大时间戳加全 1 随机位（`7` 加 25 个 `Z` 字符）。

完整包测试：41 项通过（stdio 测试前已构建）。类型检查、构建、合同门禁、工作区门禁和 diff 空白检查通过。Wayforge 回归：51 个文件、438 项通过；Wayforge 无变更。故意构造的负面架构夹具会输出预期违规，测试套件退出码为 0。

临时原始日志：`/tmp/ph0002-hotfix-red.log`、`/tmp/ph0002-hotfix-wayforge.log`。最初的停止复现程序为 `/tmp/ph0002-stop/identity-repro.mjs`，修复后为 GREEN。

本次独立热修复仅包含编码器、身份回归/边界测试和本证据记录。PH-0002 架构工作在热修复提交后才恢复。没有推送或生产集成。
