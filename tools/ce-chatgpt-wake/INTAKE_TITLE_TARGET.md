# 收件时选择桌面目标

适用于 HANDOFF-CE-TITLE-MATCH-ACTIVATION-01。当前授权允许为指定任务记录本地 CE 请求、任务标签和回复关联，并观察 Mac 上的候选会话。观察到的标题不证明任务的真实来源，也不授予向该会话输入的权限。

`auto-wake.json` 的明确配置为：

```json
"conversationGuard": {
  "mode": "explicit-only",
  "targetSelection": "desktop-at-intake",
  "captureAfterAuditSequence": 158
}
```

这里的 158 只解释本次基线；安装时必须重新取实际审计上界。保留现有 `afterAuditSequence`、会话标记、Hook 所有者和 CE 权限。`explicit-only` 时可以只读采样，但不会自动输入或发桌面通知。`title-match` 仅对有效收件记录和预先准备的回复关联生效。

现有入站控制器先写入 admission，再通过受限 Python 子进程采样，随后唤醒模型。采样队列最多 20 项，排队超过 10 秒不再启动采样；采样子进程最多运行 20 秒。采样失败但授权仍有效时继续交付任务。开始采样时 admission 必须在 30 秒内，审计序号必须超过配置上界。记录保存在私有 `stateDir/conversation-targets`，包含原始 Message ID、Exchange、admission 时间、选择策略、标题、窗口、PID、进程实例及既有精确标记。中断或失败不允许之后重新采样同一请求。

版本 2 的只读观察要求完整且唯一的 webarea、唯一输入、可验证的空闲状态及空草稿；它记录 `markerObservation` 为 `MATCH` 或 `MISSING`。缺失历史标记只表示辅助证据未观察到，并不证明标题或会话不匹配。缺标记的观察仍可用于本地 CE 消息关联，但不能授权桌面动作；未知标记状态和旧版观察也不能授权动作。新旧记录都不证明真实发起会话。

投递前会重新读取入站策略及文件修订：策略被删除、禁用或重新写入后，旧的待投递唤醒不会因恢复相同内容而触发模型回合，并记录跳过原因。同一批多条消息的采样按顺序执行；队列满、排队超时、锁忙或超过采样期限时保留经过过滤的明确原因。它们不允许事后补采。
模型实际成功调用 `ce_receive_task` 后，在 `ce_send` 前调用扩展注册的 `ce_prepare_desktop_reply`：

```json
{
  "messageId": "原始入站 Message ID",
  "taskId": "本任务标签"
}
```

`taskId` 只是 Agent 声明的关联标签，真正关联使用原始 Message ID 和 Exchange。工具自行生成 256 位随机幂等键，在关联确认完成后才返回；调用方不得自选该键，必须等待成功结果后将返回的 `idempotencyKey` 用于 `ce_send`，重试同一回复仍使用同一键。准备失败仍可提交 CE 消息；桌面效果保持抑制。Hook 只查询消息元数据的 `idempotency_key`，不读取 CE payload 列或调用 payload 工具，也不会选择“最近一个任务”。已有 CE 消息不能补造新的关联。

准备先写入关联，再读取该 Exchange 的审计上界并持久化确认。只有出站消息的审计序号高于该上界，Hook 才接受关联。生成的键在确认前不会通过工具或命令行参数提供给调用方，避免并发的调用方预先使用相同键；这依赖随机键不可预测及私有状态不被同一用户的其他进程读取，不是进程隔离保证。

自动输入和按钮输入都检查当前权限、入口、配置、原始关联、唯一窗口、窗口 ID、PID、进程实例、完整且唯一的 webarea、精确标题、既有标记、空草稿和空闲状态。填入和提交前分别重新读取。可能已经输入或提交时记录 UNKNOWN，不自动再试。

确认尚未输入后，通知显示目标标题，按钮为“回到目标会话后继续”。只认这个按钮的实际点击；通知正文点击、关闭和超时不构成同意。点击时仍然不匹配则保持 CE 消息可按 Message ID 人工取回，不向当前会话输入。一次按钮同意只能触发一次受检查的尝试；误点后不自动重新武装通知。只有观察到 notice 后才移除该任务的通知组。

本次后续观察层热更新不使用下面的首次安装工具：它仅替换两个 Python 模块，部署与恢复均不写、删除或重建入口及自动配置。入口修订检查只用于发现变化，不是锁或重开许可；操作员关闭、删除或重写入口的意图始终保留。恢复要求入口已经由操作员关闭，并在恢复后继续保持关闭。

安装工具 `install_receipt_target.py` 只安装观察器，始终保留 `explicit-only`。安装前要求完整的生产及冻结源文件哈希、仍附着的 CE 双方 Owner、无未决尝试和无活动桌面进程；同时持有现有 admission/desktop 锁。先备份旧配置及旧模块，再关闭唯一桌面入口，按依赖顺序安装（包括 `wake.py` 的退出码修复），重新取审计上界并复核哈希和 Owner。在恢复入口之前完成最终记录；恢复入口时若出错，删除入口文件以拒绝 Hook，不依赖再次写入临时文件。安装不会写 CE 权限或入站策略文件。

操作回退使用相同冻结脚本的 `--root OWNER --close-entry BACKUP/installation.json`。它先关闭入口，保留代码、已提交 CE 消息和所有尝试记录，并报告未决状态；不恢复早期自动模式。`before/owner`、`before/package` 和 `beforeModes` 保留原文件及权限，供入口关闭后的进一步恢复核对。任何代码恢复都不能当作当前 Pi 已重载的证据。

安装后需确认原 Pi 会话中的观察器接线和一条全新授权任务的实际采样及本地回复关联。当前生产保持 `explicit-only`；任何桌面输入或标题模式激活均需满足另行授权、真实来源绑定和动作时安全条件。不得给已在处理的旧请求回填目标。

仍存在同名会话和最后一次检查之后发生 UI 切换的局限。实现不自动切换会话、不启动新 Work、不重开 ChatGPT，也不扩大 CE 授权。入口关闭或切回 `explicit-only` 会使待点击通知的后续输入检查拒绝执行。

本次验证使用生产同版 Node 24.21.0。默认 Node 25.2.1 下的既有会话测试出现 `CE_HOST_UNAVAILABLE`；没有为测试修改生产 Native 信任、存储驱动或 CE 核心。
